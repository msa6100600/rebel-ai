# قرارات مراجعة الجاهزية قبل الإطلاق

راجعت ملاحظتين هندسيتين خارجيتين عن Rebel AI. الملاحظات استشارية فقط، وجرى اعتماد ما ينسجم مع الاختبارات الفعلية وبنية التطبيق.

| الاقتراح | القرار | السبب |
|---|---|---|
| حد زمني لكل مستخدم إلى جانب الحصة اليومية | اعتماد | الحصة اليومية وحدها لا تمنع الاندفاع السريع للطلبات أو الإساءة. |
| بريد إلكتروني للحساب | اعتماد البريد الآن | يحسن استعادة الحساب مستقبلاً؛ تأكيد البريد الفعلي يؤجل إلى ربط خدمة بريد موثوقة. |
| مفتاح شخصي للمستخدمين المتقدمين | منفذ | يبقى اختيارياً داخل الإعدادات، ويختبر قبل الحفظ ثم يخزن مشفراً. |
| Push-to-Talk في الإصدار الأول | منفذ ويحتاج اختبار جهاز | أبسط وأقل استهلاكاً من البث الصوتي المتصل. |
| ذاكرة وسجل محادثات سحابيان | اعتماد | ضروريان لاستمرارية الحساب عبر الأجهزة وحذف التطبيق. |
| حذف الحساب والبيانات | اعتماد | متطلب خصوصية أساسي قبل الإطلاق. |
| اشتراكات ومدفوعات | مؤجل | يحتاج قراراً تجارياً وبوابة دفع وسياسات استهلاك، وليس لازماً لإغلاق أساس الأمان. |
| مراقبة التكلفة والإساءة | اعتماد | تسجل الاستخدام لكل حساب وتضيف حداً زمنياً وسجل مراجعة تشغيلي. |

**تصحيح للمعرّفات الفعلية:** اختبارات Rebel AI الأخيرة نجحت مع `gemini-3.6-flash` و`qwen/qwen3.6-27b` و`mistral-small-latest`. لا يعتمد المسار الحالي على Gemini 1.5 Flash أو Qwen 2.5 أو Llama 3.3، لأن المعرفات السابقة لم تكن متاحة للمفاتيح المستخدمة.
