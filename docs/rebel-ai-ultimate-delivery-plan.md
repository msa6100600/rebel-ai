# Rebel AI Ultimate — خارطة تنفيذ قابلة للقياس

**الغرض:** تحويل فكرة «أفضل تطبيق ذكاء اصطناعي» إلى برنامج عمل واقعي لمطوّر واحد. لا تُقاس الجودة بعدد الأزرار أو أسماء النماذج؛ بل بزمن رد معروف، وبيانات آمنة، ونتيجة مفيدة يستطيع المستخدم حفظها أو تعديلها أو حذفها.

> **تعريف النجاح:** يتمكن المستخدم من الدخول، اختيار لغة وأسلوب، إرسال رسالة أو جولة صوتية، استرجاع ما وافق على حفظه، وتحويل الرد إلى مخرج مفيد؛ مع ظهور خطأ مفهوم عند تعذر أي مسار، ومن دون كشف بيانات حساب آخر أو الادعاء بميزة لا تعمل.

## 1. جرد المواصفات مقابل الحالة الحالية

| مطلب Rebel AI Ultimate | الحالة الحالية | الفجوة العملية |
|---|---|---|
| محادثات: حفظ، استرجاع، حذف، بحث | **منفذ** سحابياً ومعزول لكل حساب | يلزم اختبار Android دوري وسجل واضح لحالات فشل التحميل |
| نسخ الرسائل ومشاركتها | **منفذ** في دفعة 1.0.5 | يحتاج تجربة فعلية على Android لأن المشاركة تعتمد على تطبيقات الجهاز |
| نماذج متعددة وتحويل احتياطي | **منفذ**: Gemini ثم Qwen/Groq ثم Mistral | Groq غير متاح حالياً؛ يلزم إظهار صحته وتشغيل البديل من دون تأخير مبهم |
| ذاكرة طويلة مصنفة وقابلة للبحث والحذف | **منفذ** مع موافقة المستخدم ومشاريع | البحث نصي حالياً؛ لا يوجد دفتر أدلة أو تقييم ثقة بعد |
| حسابات سحابية آمنة | **منفذ**: جلسات موقعة، كلمات مرور محمية، عزل، حذف شامل | يلزم اختبار دخول وخروج فعلي على الهاتف وتحسين استرداد الحساب لاحقاً |
| ميكروفون وصوت | **منفذ كـ Push-to-Talk** | يجب اختبار الإذن والخلفية والمقاطعة على Android؛ ليس Live متصلاً |
| لغات ولهجات | **منفذ اختيار لغة نص ولهجة** | يلزم بنك تقييم مصري/فصحى/إنجليزي وتحسين الرد من نتائج الاختبار |
| واجهة إنتاجية | بطاقات مهام وإجراءات نسخ/مشاركة/إعادة صياغة **منفذة** | لا توجد Artifacts قابلة للتحرير أو ملفات مشروع بعد |

## 2. ترتيب التنفيذ لمطور واحد

### المرحلة P0 — الاعتمادية والقياس

**الهدف:** ألا يشعر المستخدم بأن التطبيق توقف أو تجاهل طلبه.

| المهمة | التسليم | معيار القبول |
|---|---|---|
| قياس مراحل الرد | زمن الشبكة، المزود، التحويل، والتفريغ/النطق بلا محتوى رسائل | تظهر لوحة المالك زمن المتوسط ونسبة الأخطاء والتحويلات فقط |
| حالة صحة المزود | بطاقة داخلية لـ Gemini وGroq وMistral: متاح/مزدحم/غير متاح | لا يوصف Groq بأنه يعمل عند 403، ولا يوقف المحادثة |
| بنك اختبار عربي | حالات ثابتة للفصحى والمصرية والإنجليزية، ودخول وحذف وذاكرة | تشغيل الاختبارات بعد كل دفعة مع نتيجة واضحة |
| اختبار Android ميداني | دخول، إرسال، صوت، مشاركة، إغلاق وفتح، شبكة ضعيفة | قائمة نتائج من هاتف فعلي، وليست معاينة ويب فقط |

**ما لا يدخل P0:** تصميم مزيد من الشاشات أو إضافة مزود جديد. إن لم يثبت الأساس، ستزيد الميزات الإحباط فقط.

### المرحلة P1 — جواب قابل للمساءلة

**الهدف:** أن يكون Rebel مفيداً في التحليل، لا مجرد مولد نص.

تبنى ميزة **دفتر الأدلة** داخل المشروع. لكل تحليل مهم: ادعاء، أدلة يضيفها المستخدم، افتراضات، حدود، درجة ثقة، وقرار المستخدم. يبدأ ذلك بالنصوص والذكريات الموجودة فقط، ولا يتطلب بحث ويب أو خدمة مدفوعة.

| المهمة | التسليم | معيار القبول |
|---|---|---|
| نموذج الدليل | بطاقات ادعاء/دليل/افتراض/ثقة داخل رد أو مشروع | يستطيع المستخدم حذف أو تعديل أي عنصر |
| قوالب تحليل عربية | مقارنة، خطة قرار، موجز مشروع، شرح، خطاب، خطة دراسة | كل قالب يضع اللغة واللهجة والأسلوب المطلوبين صراحةً |
| تقييم الرد | «مفيد/غير مفيد» وسبب مختصر بلا تخزين محتوى خارج حسابه | تظهر مؤشرات مجمعة للمالك فقط |

### المرحلة P2 — مخرجات ومشاريع حقيقية

**الهدف:** تحويل الحوار إلى عمل قابل للتعديل والتصدير.

| المهمة | التسليم | معيار القبول |
|---|---|---|
| Artifacts | مستند، خطة، جدول، قائمة قرار، أو مقتطف كود قابل للتحرير | يمكن حفظه للمشروع ونسخه ومشاركته وتصديره |
| ملفات المشروع | إضافة نص أو ملف صغير، عرض المحتوى، حذف صريح، فترة احتفاظ معلنة | لا يرفع التطبيق ملفاً أو يقرأه من دون اختيار المستخدم |
| بحث نصي بالمشروع | العثور على ذاكرة أو محادثة أو Artifact في نفس المشروع | لا تظهر نتائج مشروع أو حساب آخر |

**قرار هندسي قبل البداية:** يلزم تحديد حد حجم الملفات، مكان تخزينها، وفترة الاحتفاظ والحذف. لا يبدأ رفع الملفات قبل هذا القرار.

### المرحلة P3 — الصوت الاحترافي

**الهدف:** جعل Push-to-Talk ممتازاً أولاً، ثم تقرير Live الحقيقي على أساس قياس لا انطباع.

| المسار | ما ينفذ | بوابة القبول |
|---|---|---|
| PTT محسّن | إذن واضح، بدء/إيقاف موثوق، إلغاء نطق الرد عند جولة جديدة، رسائل خطأ مرحلة بمرحلة | ينجح على هاتف Android عند الخلفية والمقاطعة والشبكة الضعيفة |
| Live حقيقي — دراسة مستقلة | جلسة صوتية مستمرة، بث audio chunks، تفريغ/رد متدفق، مقاطعة فورية، وإدارة إعادة الاتصال | لا يبدأ قبل اختيار مزود، التحقق من السعة والتكلفة، واختبار WebSocket/WebRTC على Android |

> **قرار مهم:** Live ليس «زر أحدث». مسار Push-to-Talk الحالي يسجل ثم يرفع ثم يفرغ ثم يرد. Live يحتاج جلسة اتصال مستمرة وتدفقاً ثنائي الاتجاه ومعالجة للمقاطعة وإعادة الاتصال. لذلك لا يوضع ضمن P0 أو P1، ولا تُعلن جاهزيته قبل اجتياز اختبار ميداني وسعة معتمدة.

### المرحلة P4 — التكاملات والبحث الموثق

**الهدف:** التوسع من دون فتح صلاحيات أو مخاطر لا يمكن ضبطها.

تبدأ التكاملات بإطار موافقات: الخدمة، البيانات المطلوبة، سبب الوصول، مدة الصلاحية، وزر إلغاء. ويبدأ البحث بمصادر ظاهرة للمستخدم، وتاريخ بحث، وبيان واضح لما هو مصدر وما هو استنتاج. لا يبدأ OAuth واسع أو تنفيذ إجراء خارجي تلقائي قبل هذه الطبقة.

## 3. قرارات مؤجلة صراحةً

لا تتضمن هذه الخارطة Billing، أو اشتراكات، أو نماذج مدفوعة، أو مشاركة حسابات مزودين، أو تنفيذ أفعال خارجية نيابة عن المستخدم. كما لا تعد بذاكرة «أبدية» أو معرفة غير محدودة؛ الذاكرة الحالية تخضع لموافقة المستخدم ويمكنه تعديلها أو حذفها.

## 4. خطة التسليم لمطور واحد

| الترتيب | الدفعة | ناتج قابل للتسليم | متى تعتبر مكتملة؟ |
|---:|---|---|---|
| 1 | P0 | تقرير جودة + قياسات + اختبار Android | كل مسار أساسي له نتيجة قابلة للتكرار |
| 2 | P1 | دفتر أدلة + قوالب تحليل + تقييم | يستطيع المستخدم مراجعة أساس الاستنتاج والتحكم فيه |
| 3 | P2 | Artifacts + سياسة ملفات + بحث مشروع | يتحول الرد إلى عمل محفوظ قابل للتعديل |
| 4 | P3 | PTT ثابت، ثم قرار Live مستقل | نتيجة هاتف حقيقي وخطة سعة قبل البث المستمر |
| 5 | P4 | مصادر وتكاملات بموافقات | كل صلاحية مرئية وقابلة للإلغاء |

## 5. الدفعة التي أوصي باعتمادها الآن

**P0: الاعتمادية والقياس** هي الدفعة الصحيحة التالية. هي تعالج شكوى البطء وضعف الردود والصوت قبل بناء ميزات أكبر، ولا تضيف تكلفة أو نموذجاً مدفوعاً. بعد اختبارها على هاتف Android، تبدأ P1 (دفتر الأدلة) لأنها السمة التي يمكن أن تميز Rebel في التحليل العربي بدلاً من تقليد واجهات المنافسين.
